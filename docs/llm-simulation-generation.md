# IMEE v3 シミュレーション付きシナリオ生成

[シナリオ生成手順](llm-json-generation.md)に従い、実行経路だけを描く。実行環境は必須ではない。

1. 成功State・AND/OR・期限を定義する。
2. 外生初期Stateと、Task/作用線で成立するStateを区別する。生成元があるStateを時刻だけで初期成立させない。
3. 各Taskを固定時間またはCDFとする。入力qは接続元Stateを既定とし、複数入力だけqInputで明示する。Task途中のq入力はない。
4. 各作用線にpropagation.durationを必ず置き、実行する線だけsimulation.enabled=trueとする。到達処理はtargetのState/junctionで決まる。
5. CDF点はt,p,q。単一曲線は入力品質に共通、複数曲線なら入力q=0〜1を覆う。時間・曲線間は線形補間、未達は1−最終p、出力はq_in×点列の保持率q。
6. 合流StateのAND/ORと品質のmin/maxを確認する。OR成立後に後着情報で品質を更新しない。
7. 作用分岐はmode=effectと結果Stateを指定する。Sが対象Taskの実開始を待つ暗黙依存を加えて循環を手で点検する。開始前作用を保持して適用する設定は作らない。
8. 基準時刻でも開始条件が整合するよう受領Stateを組む。準備済みが前提なら形式的な準備過程を追加しない。
9. 同じSを複数分岐作用の発生元として使うと全対象Task開始を待つ。共有が適切か確認する。
10. 根拠のない時間・品質はnotesに仮定と記す。JSONを静的に自己点検する。任意でparse/compileを追加確認する。

実装確認のテストと、ユーザーが依頼したシミュレーション実行は別。生成しただけで実際の成功率を主張しない。詳細エラーを提示し、入力の意味を黙って変更しない。
