# IMEE Simulation

IMEE Simulationは、装備・環境・交戦の詳細挙動をモデル化せず、外部解析によって得られたTask-level performanceをMission Thread上で伝播させ、Mission-level effectivenessおよび必要Capabilityを評価する。

Task CDF・作用線の伝搬CDF、確率分岐・作用分岐、作用線からのState到達、State/作用線のw伝播、Monte Carlo、Mission成功条件・期限、時間分布、Criticality、Taskの時間/wの感度分析・要求境界の推定を扱います。座標・軌道・センサ・交戦物理、再試行、ランダムW、Resource/数量は扱いません。

## 操作

1. **Simulation → シミュレーション例を開く**。文書置換はUndoできます。例は `examples/simulation.json` にもあります。
2. CDF有効Taskは実線、固定所要時間（FIX）のTaskは二重線です。保存済みCDFが無効ならFIXとして描画します。分岐後の結果線は固定遅延なので二重線です。Task編集の **Simulation / Performance** でCDFを編集します。最終累積確率が1未満なら残りは未達です。追加依存State、w入力・出力、中止Stateも設定できます。
3. 分岐を追加した後、Task編集の **分岐の実行設定** で確率/作用モードを明示します。作用線編集の **Simulation / 作用線** でw伝播・作用分岐・State到達を設定し、伝搬時間を固定またはCDFで指定します。実行作用線もCDFは単線、FIXは二重線で、極性の波形は保持します。State編集で出力wとAND/OR合流を設定します。
4. **成功条件・実行設定** で成功State（AND/OR）、期限、試行数、Seedを設定し、**Monte Carlo実行**。結果に開始・終了・待ち・入力w・CI、分岐/中止数、作用線の伝搬時間・CI・未達・適用状況、第1試行の到達履歴を表示します。
5. **感度分析 / 要求逆算** でTask、時間/w、評価範囲、点数、各点の試行数、Mission要求成功率を設定します。既定はWilson 95%区間下限で要求判定します。成功率推定値による判定も選べます。
6. 実行完了後に **結果をシナリオ図に反映** を押すと、ダイアログを閉じて線幅と割合を図へ重ねます。ツールバーの **結果表示** でON/OFFを切り替えます。表示中のSVG / PNG出力にも割合と凡例を含めます。
7. 実行・分析は中断できます。JSON出力には実行時のMissionと結果を保存します。モデル編集で結果を無効化し、View変更では保持します。図上の時刻を書き換えません。二重線は所要時間/遅延の固定を表し、依存条件による開始時刻の変動は許します。

## シナリオ図への結果反映

すべての割合の分母は**全試行数**です。通常Taskは正常完了数、分岐結果線はその結果を選択した回数、実行作用線は実際に適用された回数を使います。未達・開始不能・中止はTaskの正常完了に、early / late・伝搬未達・発生なし・未適用の保持は作用適用に含めません。期限を超えたTask完了・分岐選択は各経路の割合には含め、Mission成功率は期限内だけを数えます。各Stateの到達率や時刻ごとの通過確率を表示するものではありません。

分岐Taskの主線はjunctionで区切ります。分岐前の区間は「通常完了した試行＋その分岐以降で結果を選択した試行」、分岐後の通常経路はそこから分かれた試行を除いた割合になります。通常接続先を持たない確率分岐Taskも、結果へ進んだ試行を主線の通過として数えます。これは基準図の接続を通る結果経路の割合で、作用がjunction.timeに届いた確率ではありません。

迎撃例の5,000試行・Seed 17では、中間飛行の分岐前100%、中間撃破71.7%、終末への継続28.3%、終末撃破21.0%、着弾への継続7.3%です。割合は1桁の小数で丸めます。0%は細い灰色線として残し、小さい非ゼロ値は `<0.1%`、1未満の高確率は `>99.9%` として、0% / 100%と区別します。

線の外幅は `1.6 + 6.4 × 割合` px（0%で1.6px、100%で8px）です。CDFは単線、FIXは外幅の40%を中央の空白にした二重線で、波形・Actor色・接続位置・通常のラベルを維持します。割合ラベルは線の近くへ別に配置し、線・ラベルのツールチップで割合の意味と回数/全試行数を確認できます。凡例に試行数、Seed、Mission成功率、分母と基準時刻であることを表示します。

compact / spacedの折りたたみは個別の結果を維持します。singleの集約線は、相関した複数経路の周辺集計から正しい合算率を得られないため、割合を付けません。展開すると個別の割合を確認できます。全階層の画像出力には個別の結果を表示します。並列経路はそれぞれ100%になりえます。

表示状態と実行結果はセッション内で保持し、シナリオJSONに線幅や結果割合を保存しません。View・ズーム・選択では結果を保持し、モデル編集・文書置換・再実行開始で図の結果を解除します。中断・エラー・感度分析の途中結果を図へ反映しません。

## CDFの帯プレビュー・ホバー

Task・作用線のCDF編集画面は、定義されたw範囲でのCDFの上下限を薄い帯、入力欄のwに対応するCDFを濃い線で表示します。w=0とw=1が定義されていれば0〜1全体を含みます。w方向の補間は線形なので、途中のw曲線も含めた全定義曲線の最小・最大が上下限となります。時間方向の曲線交差も帯の境界に反映します。帯は性能パラメータによる変化幅で、信頼区間やランダムWの確率分布ではありません。

部分的なw範囲しか定義されていなければ、その範囲を明示し、外挿しません。単一wしかない場合は「幅は未定義」と表示し、別wの曲線を追加して比較できます。濃い線の「表示w」は設定画面の基準値です。作用線のCDF入力wが空欄なら0を表示し、実行時の継承wを自動推定しません。

キャンバスのCDF有効Task・作用線の線やラベルにポインターを置くと、同じ帯グラフをポップアップします。キーボードで線へフォーカスした場合も表示します。固定時間の線・固定分岐後の線・折りたたみ集約線にはCDFを表示しません。ポップアップは操作を受け取らず、離脱、クリック、ドラッグ、Esc、スクロール、ウィンドウ変更・モデル再描画で閉じます。表示だけで文書やシミュレーション結果を変更しません。

## 迎撃例

敵Actorは**弾道ミサイル本体だけ**。味方は広域レーダー、中央管制、中間軌道撃破用ユニット、終末軌道撃破用ユニットです。

探知は「弾道ミサイルの発射State → 探知作用線（伝搬CDF）→ レーダーの目標探知State」。発射から探知成立までのCDFを作用線で抽選し、有限の到着なら目標探知Stateを成立させます。未達なら追尾・判断・迎撃は開始できません。ミサイルの基準飛行は並行して進みます。

探知・追尾 → 判断・指令 → 中間迎撃 → 未撃破なら終末迎撃。各迎撃ユニットは「準備完了 → 発射指示（固定10秒） → 迎撃ミサイル発射 → 軌道迎撃（CDF） → 迎撃」と進みます。発射指示は準備・指令・該当飛行段階への到達を待ち、追尾wを発射Stateから迎撃Taskへ引き継ぎます。CDFは発射から敵の撃破達成までの時間・未達を表します。迎撃ユニット側の「迎撃」Stateは撃破作用が成立した結果で、作用線が敵の飛行Taskを分岐させ、**敵ミサイル側の撃破State**へ到達します。中間撃破後は敵の残りのTaskと終末迎撃を中止し、着弾Stateに到達しません。成功条件は敵の「中間軌道で撃破 OR 終末軌道で撃破」、期限180秒です。

追尾Stateの外部入力 `w=0.25` を追尾情報・管制判断・指令から両迎撃Taskへ伝播します。探知達成率0.98、w=0.25での中間迎撃達成率0.7375、終末迎撃達成率0.7875。共通の探知成否、迎撃の独立抽選、時間窓内での作用を仮定すると、解析的成功率は `0.98 × (1 − (1−0.7375) × (1−0.7875)) = 0.925334375`。5000試行・Seed 17では92.70%、中間撃破3586試行・終末撃破1049試行です。基準図では中間発射70秒・迎撃100秒、終末発射130秒・迎撃160秒です。発射後の達成時刻はCDFの抽選で変動します。

時刻・CDF・wは説明用の架空の入力です。実在装備の性能、撃破物理やwの原因をIMEEが計算しているわけではありません。

## 実行規則

- Taskは1試行1回。通常接続先と**すべての分岐先**を潜在的なState生成元に含めます。生成元（Task・State到達作用線）がないStateだけが初期Stateで、図上の時刻に到達します。未選択の分岐先や未達の作用線入力先を初期Stateにはしません。
- Stateの生成元が複数なら `simulation.join: "all"`（既定）はすべての到達を待ち、`"any"` は最初の到達を採用します。代替経路の合流にはanyを指定します。到達後の再活性化はありません。
- Taskは接続元・追加依存・選択したw入力State・到着待ちのw作用線がそろうと開始します。図上の開始時刻でクランプしません。Actorは自動的な排他Resourceではありません。
- CDF無効/未設定なら図上のTask所要時間を使います。無効は実行除外ではありません。CDF抽選が∞なら通常完了せず後続は開始不能ですが、実行中の作用による中断・分岐は可能です。
- `cancelOnStateIds` のいずれかに到達すると、そのTaskが未開始/実行中なら中止します。完了済みの到達を巻き戻しません。
- 作用の極性・分類・ラベルから実行規則を推測しません。`causalLink.simulation.enabled: true` の作用線だけを実行します。表示専用の作用線があれば警告します。
- State出力は実到達時刻、Task出力端点は図上の進捗割合 × 抽選した所要時間で発生します。中断後の未到達端点は出力しません。Actor出力は端点の図上時刻（wは固定指定必須）です。
- 作用線の固定遅延は明示値、または図上の入力端点時刻−出力端点時刻。伝搬CDFが有効ならこの固定値に代えてCDFから抽選します。固定値を加算しません。入力端点の図上時刻は実到着時刻を固定しません。
- 同時刻ではState/出力端点、作用到着、確率分岐、通常完了、Task開始の順で処理します。作用を発生させるTaskの通常完了は受け手の通常完了より先です。終了時刻と同時の作用は受け手を分岐できます。同時に成立する競合作用は文書順で最初の適用を採用します。
- 依存/State到達作用/w到着待ちの循環、同時刻の作用完了順の循環、Task期間外の実行出力端点、実行モード未指定の分岐を実行前に拒否します。古い分岐文書の読込・編集は可能です。

## CDFとw

CDFは `F(t|w)=P(T≤t)`。時間単位は文書のtime.unit。tは非負の狭義昇順、pは0〜1の単調非減少。曲線はw（0〜1）の狭義昇順、最終p+pInfinity=1（許容1e-10）。t>0の最初の点までは(0,0)から線形補間し、t=0のp>0は即時達成です。最終点以降は平坦で残りを∞とします。w方向は隣接曲線の時間点の和集合でCDFを線形補間し、外挿しません。

```json
{
  "simulation": {
    "enabled": true,
    "w": 0,
    "waitForStateIds": ["orders"],
    "wInput": {"stateIds": ["track"], "waitForLinks": true, "combine": "max"},
    "outputW": 0.25,
    "cancelOnStateIds": ["already-destroyed"],
    "performanceModel": {"type": "cdf", "degradationInput": "w", "curves": [
      {"w": 0, "points": [{"t": 5, "p": 0.2}, {"t": 20, "p": 0.9}], "pInfinity": 0.1},
      {"w": 1, "points": [{"t": 5, "p": 0.05}, {"t": 20, "p": 0.55}], "pInfinity": 0.45}
    ]}
  }
}
```

開始時に選択Stateと到着済みw作用線の最大wを採用し、入力がなければTaskの固定w（省略0）を使います。開始後のTask入力は適用せずlateとして集計します。`waitForLinks: true` なら実行指定の入力w作用線すべてを待ちます。選択Stateは常に到達待ちです。Task出力はoutputW指定があれば固定値、なければ採用w。State出力は固定simulation.w指定が優先し、なければ到達Task・受信作用線の最大wです。Stateへの後着wは以降のTask入力に利用できますが、State出力作用線は到達時に1回だけ発生します。

入力源の潜在的なwがCDF範囲を外れる場合、実行前にエラーにします。wの原因・ランダムW・環境相関は計算しません。各Task・作用線CDFの時間抽選は独立で、共通の依存/伝播を通じた結果の関連は表現します。

## 分岐と作用線データ

```json
{
  "id": "flight", "fromStateId": "flying", "toStateId": "next-phase", "label": "飛行",
  "junctions": [{"id": "effect-port", "time": 90, "simulation": {"mode": "effect"},
    "outcomes": [{"toStateId": "destroyed", "label": "撃破", "delay": 0}]}]
}
```

```json
{
  "id": "kill-effect", "source": {"type": "state", "id": "kill-action"},
  "target": {"type": "task", "id": "flight"},
  "propagation": {"duration": 0},
  "polarity": "negative", "label": "撃破作用",
  "simulation": {"enabled": true, "type": "branch",
    "junctionId": "effect-port", "outcomeStateId": "destroyed", "stopTargetActor": true, "holdUntilStart": false}
}
```

- `mode: "effect"`：作用到着時、受け手Taskが実行中なら指定結果へ移り、通常接続先と残りの分岐/出力を取り消します。開始前はearly、完了/中止後はlate。holdUntilStartなら開始前の作用を保持します。stopTargetActorは受け手Actorの他の未開始/実行中Taskも中止します。結果Stateは中止後も指定遅延で到達します。
- `mode: "probability"`：抽選した所要時間の進捗に応じて分岐点へ到達し、outcomesのprobabilityで結果を1つ選びます。合計≤1、残りは通常経路です。通常接続先がない最終分岐は合計1必須。同一Task内のモードは統一します。∞では進捗0以外の分岐点に到達しません。
- outcome.delay省略時は図上の結果State時刻−分岐時刻。分岐確率はTask未達確率の代替ではなく、分岐点に到達した条件下の選択確率です。
- w作用線は `propagation: {duration:0}` と `simulation: {enabled:true,type:"w",w:0.25}` のように、伝搬時間と到着後の効果を分離します。w省略なら出力元のwを引き継ぎます。入力先はTask/State、Actorは不可です。

新しいState・Junction・作用線参照は読込時に検証します。コピーで内部参照を再マップし、削除時に失われた参照を除去します。作用分岐をTask編集で削除/変更した場合、その分岐を指定した作用線も削除します。Undoで戻せます。

## 作用線の伝搬時間・CDF・State到達

作用線は到達絶対時刻を保存せず、`source` とトップレベルの `propagation` から到着を決めます。

固定伝搬:

```json
{
  "id": "track-report",
  "label": "追尾情報",
  "polarity": "positive",
  "source": {"type": "state", "id": "track-ready"},
  "target": {"type": "task", "id": "decide"},
  "propagation": {"duration": 4},
  "simulation": {"enabled": true, "type": "w"}
}
```

図上の基準到達時刻は `source基準時刻 + propagation.duration` です。`target.time` は保存しません。

CDF伝搬:

```json
{
  "id": "observation", "label": "探知", "polarity": "positive",
  "source": {"type": "state", "id": "launched"},
  "target": {"type": "state", "id": "detected"},
  "propagation": {
    "duration": 20,
    "w": 0,
    "performanceModel": {"type": "cdf", "curves": [
      {"w": 0, "points": [{"t": 5, "p": 0.2}, {"t": 20, "p": 0.9}], "pInfinity": 0.1}
    ]}
  },
  "simulation": {
    "enabled": true,
    "type": "state"
  }
}
```

- `propagation.duration` は必須の非負値で、図上の基準到達位置を決めます。
- CDFのtは作用発生から到着までの**経過時間そのもの**です。実到着時刻 = 実発生時刻 + 抽選時間。
- CDFを使う場合、抽選時間を `duration` に加算しません。`duration` は表示・基準整合用です。
- CDFで∞なら到着せず、受け手のw更新・分岐・State成立は起こりません。
- `propagation.w` があればCDFの固定入力、なければ発生元の出力wを使います。`simulation.w` は受け手へ渡す固定wで、CDF入力とは別です。
- `type: "state"` は入力先State専用。State targetでは、基準整合のため `target State.time = source基準時刻 + propagation.duration` を要求します。
- `type: "w"` のState入力はw更新だけで、Stateを成立させません。
- `type: "branch"` は到着時の受け手Taskの実行状態で判定します。effect分岐では、基準到達時刻を指定junction.timeへ一致させます。
- 結果Stateまでの `outcome.delay` は分岐後の別工程として残ります。
- 表示のみの作用線でも `propagation.duration` は持ちます。ただし `simulation.enabled` がfalse/未設定なら実行依存には使いません。
- 旧 `simulation.delay` / `simulation.propagation` / `target.time` は使用しません。
- 読込時に伝搬時間・CDF・参照を検証し、実行前にw範囲と依存循環を追加確認します。作用線の感度分析・要求逆算は現段階では未対応です。

## Mission統計・Criticality

文書simulationは `{successStateIds:[...],successMode:"all"|"any",deadline:null|number,iterations,seed}`。成功条件到達時刻はANDなら最大、ORなら最小で、期限以内なら成功。95%区間は二項比率のWilson区間で、入力CDF自体の誤差は含みません。

- 完了時間P50/P90は到達した試行のみ（期限超過も含む）。到達なしならnull。
- Mission CDFは時刻までの到達数/全試行数。未達確率を取り除いて正規化しません。
- Task開始/待ち/入力wは開始した試行、通常終了時刻は通常完了した試行の分布です。分岐・中止は通常完了/未達/開始不能と分けます。
- Critical PathはMission到達を成立させた実際の依存・作用の因果経路を逆にたどります。ANDは最後、ORは最初の到達を起点にし、同時刻の依存はすべて含めます。作用で中断した敵飛行の予定残時間をCriticalと数えず、撃破作用の発生元をたどります。
- CI = Criticalだった試行数/全試行数。未達試行では未定義として数えません。成功時CIは期限内成功試行が分母です。
- 作用線の伝搬時間P50/P90は有限の到着試行（未適用も含む）、wは発生した作用のCDF入力wです。failedは伝搬CDFで∞、unavailableは発生元が未達・中止などで作用を発生しなかった試行。両者を区別します。作用線CIもMission到達を決めた因果経路をたどり、全試行または期限内成功を分母に集計します。
- 第1試行の履歴は代表値ではありません。結果JSONにState時刻・Task状態/開始終了/採用w・作用の発生時刻・伝搬時間・CDF入力w・到着時刻・未達/適用状況・分岐を記録します。

Seedはuint32、試行数1〜100,000。State+Task+実行作用線+分岐の数×試行数≤500万、感度分析全体≤2000万。バッチ処理で画面に制御を返します。最終統計は同期処理です。同一文書・設定・Seed・バッチサイズの違いで結果は一致します。Taskの抽選を予約した後、CDF有効の作用線の抽選も発生成否に関わらず文書順で予約しますが、文書順序/構造を変えた際の割当は保証しません。

## 感度分析と要求逆算

時間介入は `Ti=t` に固定し、**対象Taskの達成を仮定して未達質量を除きます**。Taskが依存で開始不能の場合は開始不能のままです。これは実CDFに対する十分条件や装備の保証ではありません。w介入は対象Taskの採用wを固定し、CDFからの抽選と入力到着待ちを保持します。出力w固定がなければ変更wも後続へ伝播します。

基準ケースと各点は同じSeedで時間・分岐の乱数を対応させます。各点に成功率・Wilson区間・CI・完了時間を記録します。要求は推定値または95%区間下限≥要求成功率で判定。達成した先頭範囲から未達への境界を最大8回二分評価（UIは6回）します。結果は達成/未達の評価値の間として返し、線形補間した厳密閾値を主張しません。

全点達成なら上限未特定、全点未達なら評価範囲内に達成点なし、未達後に達成点が現れたら非単調として一律の上限を導出しません。評価点間の未検出の非単調性も保証しません。Capability Gapは基準成功率の要求からの不足と、Task性能側の評価境界として示します。実装備の不足や必要CDF全体を自動導出するものではありません。

## Node API

外部依存のないclassic script/CommonJSです。

```js
const S = require('./js/simulation.js');
const A = require('./js/sensitivity.js');
const result = S.run(mission, {iterations: 5000, seed: 17});
const analysis = A.run(mission, {
  taskId: 'midcourse-intercept', parameter: 'duration', values: [5, 10, 20, 40, 60],
  iterations: 1000, seed: 17, targetProbability: 0.8, criterion: 'lower95', refineSteps: 6
});
```

画面はcreateRun/createSensitivity → step(batch) → result()を使います。compile/trialで1試行のMap・Critical集合を調べられます。∞は試行内部だけに使い、結果JSONは有限数またはnullです。データモデルはversion 2を維持します。
