# サンプルの読み方

すべて架空の検討例です。時間、能力、TRLは表示・分析機能を説明するための仮定です。予定の分岐先を同時に達成した実績として扱いません。

## 沿岸監視：識別した接触を通報する

目的は、不明接触の識別結果を母船へ届けることです。

1. 監視UUVが2〜16分に海域を捜索し、接触を探知します。ここまでを実績として表示します。
2. 識別担当が情報を受け、特徴を照合します。一致なら35分に識別済、不一致なら識別保留となり、追尾・再観測で58分に追加情報を得る予定です。
3. 識別できた場合、通信担当が38分から通報します。49分の判定点には、敵の妨害Taskから負の因果が入ります。
4. ACKを受信すれば56分に通報完了。応答がなければ通信方式を切り替え、84分までに再送・ACK確認する予定です。

再観測後の再識別や、代替回線も妨害されるケースはこの図の範囲外です。負の因果は失敗の確定を意味せず、判定点に影響する要因を示します。再送の成功確率も評価していません。

## 海底調査：2機の分担と母船の判断

A機は広域捜索、B機は候補への接近・撮像、母船は報告の照合を担当します。確認に成功すると記録を確定して回収を指示します。不鮮明な場合は別角度で再走査し、未確定であることを母船へ報告、再調査の計画につなげます。

「水中調査班」を折りたたむと、A機・B機の詳細が隠れ、母船との確認報告・未確定報告・回収指示が残ります。元の時刻は変化しません。初期表示では展開し、何を折りたたむのかを確認できるようにしています。

## 技術Gap：時間が間に合っても能力が不足する

電波監視が妨害源を探知・測位し、指揮所が介入を決定、介入担当へ指令します。介入Taskの48分の点から、敵の妨害Taskの48分の点へ負の因果が接続します。敵Taskの実行期間は20〜68分です。

探知・判断・指令・介入の経路と時間窓は成立しますが、「妨害源追尾制御」を研究段階、TRL4と仮定しているため、SOME / ALLは未充足になります。このTechnologyをexistingに変更すると登録条件上は充足します。実世界の成功を保証する判定ではありません。

Bindingは電波探知、情報融合・指揮、指向性送信装置、妨害源追尾制御の役割に分けています。味方の受信を守る耐妨害通信で敵の送信活動自体を抑制できる、という意味付けにはしていません。

Gap Viewの注記は未成熟な技術に絞っています。Technology Viewへ切り替えると既存技術を含むBindingの注記を確認できます。
